# Known issues

Every defect or limitation of the reviewed gateway and fabric versions that this skill knows about, listed
once. Other files link a `KI-nn` ID with at most a one-line summary; the full row is only here. Read the row before you rely on a
feature it names, and whenever what you see contradicts the documentation or the user's intent.

When you hit one:

1. Apply the workaround first, so the user's task still gets done safely.
2. Then tell the user it is a known defect of this version, name the ID, and say what the
   workaround costs them.
3. Never present a workaround as the product's intended behaviour.

The Status column says how the defect is known:

- **source**: read from the gateway or fabric source at the reviewed version; the cell names the file,
  and the function or type where there is one. "(inference)" marks a consequence reasoned from the code,
  not run.
- **reproduced on a running gateway**: the symptom was also seen on a running gateway at the reviewed
  version.
- **partly reproduced**: a running gateway showed part of the symptom; the cell says which part, and the
  rest is read from source.
- **not yet reproduced**: the code path is read, but the symptom has not been reproduced on this version.
  Treat the row as likely, and check with the Detect step before acting on it.
- **withheld**: a security defect whose Detect step and source are not published until the gateway's
  maintainers publish an advisory for it. Treat the row as real and apply its workaround.

Detect steps that send traffic assume a disposable test surface. Never run them against a surface
that serves real callers without the user's agreement.

## Check one surface against this list

Several issues show in a surface's saved JSON. This read-only check prints the ones a surface
triggers. It changes nothing; read each printed row below before you act on it.

```bash
SURFACE_ID=${SURFACE_ID:?set SURFACE_ID to the surface to check}
fabric agent-gateway surfaces get "$SURFACE_ID" -o json > surface.json
jq -r '
  (if .target.policy == null and .access_point.inbound_policy == null
     then "KI-01: caller_context.mode is inert and no policy is attached, so nothing rejects an unidentified caller" else empty end),
  (if any(.outbound_credentials[]?; .consent_mode == "pre_authorize")
     then "KI-02: pre_authorize behaves as on_demand" else empty end),
  (if (.access_point.protocol // "a2a") == "a2a"
      and any(.outbound_credentials[]?; (.required_for | type) == "object")
     then "KI-16: a tools list in required_for never matches on A2A" else empty end),
  (if ((.transit.points // []) | length) > 0
     then "KI-08: transit points present; the transit token is not authentication" else empty end),
  (if .transit.transit_policy != null
     then "KI-20: transit.transit_policy is not enforced" else empty end),
  (if any(.access_point.inbound_policy, .target.policy, .target.response_policy;
          . != null and .require_agent_context == true)
     then "KI-21: require_agent_context has no effect outside a transit-point policy" else empty end),
  (if .target.networking.timeout != null and .target.networking.timeout.connect_secs != 10
     then "KI-30: connect_secs is ignored" else empty end),
  (.default_variant_id as $d
   | if $d != null and any(.variants[]?; .id == $d and .enabled == false)
     then "KI-31: the default variant is disabled" else empty end)
' surface.json
```

Gateway-wide issues such as KI-03, KI-05, KI-07, KI-15, KI-46, KI-54, KI-55, KI-58 and KI-59 do not show in a
surface; check them once per gateway with the Detect column.
